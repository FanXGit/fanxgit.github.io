# # 一、概念（Concept）：AI Agent 是什么？

# ## 通俗解释（一句话懂）

AI Agent 就是一个「会自己思考、自己干活、不用你一步步指挥」的AI程序——你只需要告诉它“要做什么”，它自己会想“怎么做”，甚至做错了会自己修正，不用你全程盯着。

比如：你让它“用Java写一个计算1-100求和的程序，并且运行出结果”，它不会只给你代码，还会自己调用Java编译器、运行代码、检查结果，直到完成目标。

# ## 核心定义（不绕弯，记重点）

AI Agent（智能体）：基于大模型，具备「自主感知、自主决策、自主执行、自主反思」能力，能独立完成复杂任务的自动化AI系统，本质是“可自动循环工作的Java（或其他语言）程序+AI大脑”。

# ## Java开发者视角（重点记）

对我们Java程序员来说，AI Agent 不是“高深的新技术”，而是「用Java代码调用大模型API，再结合我们熟悉的Java工具（编译器、数据库、SpringBoot等），实现“自动干活”的程序」——核心还是Java开发，只是多了“AI自主决策”的能力。

# # 二、作用（Function）：AI Agent 有什么用？好处在哪？

# ## 核心作用（解决什么问题？）

一句话：帮Java开发者「省时间、减工作量」，把重复、繁琐、有规律的工作，交给AI Agent自动完成，你专注于核心开发（比如架构设计、复杂业务逻辑）。

# ## 具体好处（Java开发者最关心的3点）

  1. 自动完成重复工作：比如自动生成Java实体类、自动写接口测试代码、自动排查简单的Java报错（如空指针、语法错误），不用手动敲重复代码；

  2. 降低复杂任务门槛：比如你要做一个“Java+MySQL的用户管理系统”，不用自己一步步拆解需求、写代码、测试，Agent会自动拆解步骤，逐步完成；

  3. 减少人为错误：Agent会自己检查代码语法、逻辑错误，比人工排查更高效（比如忘记写try-catch、SQL拼写错误，它能自动修正）；

  4. 拓展本地能力：通过本地Skill、MCP调用，让Agent能操作本地文件、调用本地Java程序，打破“只能依赖云端API”的限制，适配更多离线场景。

# ## 相比其他方案的优势（通俗对比）

方案 核心特点 劣势
AI Agent（Java版） 自主决策、自动执行、自动纠错，可调用本地Skill和MCP，全程不用手动干预 需要简单配置，依赖大模型API，本地工具编写需基础Java开发能力
普通Java开发（手动） 完全可控，灵活度高 重复工作多，效率低，容易出错，无法实现自主决策
普通AI工具（如Copilot） 辅助写代码，省点敲代码时间 不能自主完成完整任务，无法调用本地程序，需要人工指挥

# # 三、怎么下载（How to Download）：需要的工具/官网在哪？

注意：AI Agent 不是“一个单独的软件”，而是「Java项目+大模型API+辅助工具」的组合，我们需要下载3类核心资源（均为正版官方渠道，安全无广告）。

# ## 1. 核心工具：Java开发环境（必装）

  • 官网：https://www.oracle.com/java/technologies/downloads/ （Oracle JDK），或 https://adoptium.net/ （OpenJDK，免费无版权问题，推荐）

  • 下载版本：Java 11 或 Java 17（稳定版，适配所有Agent框架，也适配本地Skill和MCP调用）

  • 简单说明：和我们平时开发Java项目的环境完全一样，不用额外学习，装完配置环境变量即可，是本地Skill、MCP编写和运行的基础。

# ## 2. Agent框架（Java版，必装）

推荐用「LangChain4j」（Java专属Agent框架，最流行、最易上手，适配所有主流大模型，支持本地Skill和MCP调用）

  • 官网：https://langchain4j.dev/ （官方文档全是Java案例，包含工具编写、本地调用相关教程，适合Java开发者）

  • 下载方式：不用单独下载，在Maven项目中添加依赖即可（后面实践环节会具体写，新增本地调用相关依赖）。

# ## 3. 大模型API（必用，Agent的“大脑”）

Agent需要大模型（如豆包、GPT-4o）来“思考决策”，我们需要获取大模型的API密钥（免费额度足够入门）

  • 推荐：豆包API（中文友好，免费额度多，不用科学上网，支持本地工具调用的指令解析）

官网：https://www.doubao.com/ → 注册账号 → 进入“开放平台” → 申请API密钥（免费额度：新用户有100万token，足够练手）

  • 备选：GPT-4o API（需要科学上网，官网：https://platform.openai.com/ ，新用户有少量免费额度）

# ## 4. 辅助工具（可选，提升效率）

  • IDE：IntelliJ IDEA（写Java代码、本地Skill和MCP，官网：https://www.jetbrains.com/idea/ ，社区版免费）

  • 数据库：MySQL（用于后续实践案例，官网：https://dev.mysql.com/downloads/ ，免费）

  • 本地调试工具：Postman（可选，用于调试MCP接口，官网：https://www.postman.com/ ，免费版足够）

# # 四、怎么玩（How to Play）：基础使用步骤+Java命令/操作

核心逻辑：先搭建Java+LangChain4j环境 → 配置大模型API密钥 → 编写简单的Agent代码 → 运行Agent，让它自动干活。

全程不用复杂操作，和我们平时写Java小程序完全一样，分4步走（每步都有具体命令/代码）。

# ## 步骤1：搭建Java项目（IDEA中操作）

  1. 打开IDEA → 新建「Maven项目」（GroupId随便填，ArtifactId填agent-demo，JDK选择11/17）；

  2. 等待项目初始化完成（和普通Java Maven项目一样）。

# ## 步骤2：添加Agent依赖（LangChain4j）

打开pom.xml，添加以下依赖（直接复制粘贴，刷新Maven即可下载，新增本地调用相关依赖）：

<!-- LangChain4j 核心依赖（Java Agent框架） -->
<dependency>
    <groupId>dev.langchain4j</groupId>
    <artifactId>langchain4j-core</artifactId>
    <version>0.24.0</version>
</dependency>

<!-- 豆包API依赖（Agent的大脑，中文友好） -->
<dependency>
    <groupId>dev.langchain4j</groupId>
    <artifactId>langchain4j-doubao</artifactId>
    <version>0.24.0</version>
</dependency>

<!-- 本地工具/skill调用依赖（核心新增） -->
<dependency>
    <groupId>dev.langchain4j</groupId>
    <artifactId>langchain4j-tools</artifactId>
    <version>0.24.0</version>
</dependency>

<!-- Java 基础工具依赖（简化代码） -->

    <scope>provided</scope>

    &lt;version&gt;5.3.1&lt;/version&gt;

# ## 步骤3：配置大模型API密钥

  1. 去豆包开放平台获取API密钥（前面已说，复制密钥）；

  2. 在Java项目中创建一个配置类（Config.java），粘贴密钥（不用记复杂配置，直接用）：

import dev.langchain4j.model.doubao.DoubaoChatModel;

public class Config {
    // 替换成你自己的豆包API密钥
    private static final String DOBAO_API_KEY = "你的豆包API密钥";

    // 初始化大模型（Agent的大脑）
    public static DoubaoChatModel getDoubaoModel() {
        return DoubaoChatModel.builder()
                .apiKey(DOBAO_API_KEY)
                .build();
    }
}

# ## 步骤4：基础Agent操作（核心命令/代码）

Agent的核心操作就3个：创建Agent → 给Agent下达目标 → 运行Agent，看它自动完成。

基础代码（直接复制到Main类，运行即可）：

import dev.langchain4j.agent.Agent;
import dev.langchain4j.agent.AgentExecutor;

public class AgentHelloWorld {
    public static void main(String[] args) {
        // 1. 获取大模型（大脑）
        var model = Config.getDoubaoModel();

        // 2. 创建Agent（给大脑加“自主执行”能力）
        Agent agent = Agent.builder()
                .chatModel(model)
                .build();

        // 3. 给Agent下达目标（让它自动干活）
        String goal = "用Java写一个简单的Hello World程序，并且输出运行结果";
        String result = AgentExecutor.execute(agent, goal);

        // 4. 打印Agent的执行结果
        System.out.println("Agent执行结果：\n" + result);
    }
}

# ## 实践2：自动生成Java实体类（基础应用，常用）

# 目标

让Agent自动生成“用户实体类（User.java）”，包含id、username、password、age、createTime字段，并且添加getter/setter、toString方法（平时开发中最常用的重复工作）。

# 代码（修改Main类即可）

import dev.langchain4j.agent.Agent;
import dev.langchain4j.agent.AgentExecutor;

public class AgentGenerateEntity {
    public static void main(String[] args) {
        // 1. 获取大模型
        var model = Config.getDoubaoModel();

        // 2. 创建Agent
        Agent agent = Agent.builder()
                .chatModel(model)
                .build();

        // 3. 下达目标（明确要求，让Agent不跑偏）
        String goal = "用Java生成一个User实体类，要求：" +
                "1. 包含字段：id（Long类型）、username（String类型）、password（String类型）、age（Integer类型）、createTime（LocalDateTime类型）；" +
                "2. 添加getter、setter方法；" +
                "3. 添加toString方法；" +
                "4. 导入必要的包（如java.time.LocalDateTime）；" +
                "5. 代码规范，符合Java开发习惯。";

        // 4. 执行Agent
        String result = AgentExecutor.execute(agent, goal);

        // 5. 打印结果
        System.out.println("Agent生成的User实体类：\n" + result);
    }
}

# ## 一、本地Skill 是什么？（通俗解释+核心作用）

# ### 1. 通俗解释（一句话懂）

本地Skill 就是「你自己用Java写的、放在本地电脑上的“小功能程序”」，比如“本地文件读取”“本地Excel解析”“本地代码编译”，Agent可以像调用API一样，自动调用这些本地小功能，完成本地任务。

举个例子：你让Agent“读取我本地D盘的test.txt文件，并且统计文件中的字数”，Agent就会调用你写的「本地文件读取Skill」，完成读取和统计，不用依赖云端工具。

# ### 2. 核心作用

  1. 打破云端限制：不用联网也能让Agent干活（比如离线读取本地文件）；

  2. 适配本地场景：处理本地数据、调用本地程序，解决云端Agent无法操作本地资源的问题；

  3. 自定义功能：根据自己的需求，编写专属Skill（比如你公司的内部工具，Agent可以直接调用）。

# ### 3. Java案例：编写第一个本地Skill（本地文件读取）

# 步骤1：编写本地Skill类（核心，用LangChain4j注解标识）

import dev.langchain4j.agent.tool.Tool;
import java.io.BufferedReader;
import java.io.FileReader;
import java.io.IOException;

/**
 * 本地Skill：读取本地文件（Agent可自动调用）
 * 注解@Tool：告诉LangChain4j，这个类是Agent可以调用的工具（Skill）
 */
public class LocalFileReadSkill {

    /**
     * 技能方法：读取指定路径的本地文件内容
     * @param filePath 本地文件路径（比如：D:/test.txt）
     * @return 文件内容
     */
    @Tool(description = "读取本地文件内容，参数是文件的完整路径（如D:/test.txt），返回文件中的所有文本内容")
    public String readLocalFile(String filePath) {
        // 核心逻辑：Java读取本地文件
        StringBuilder content = new StringBuilder();
        try (BufferedReader br = new BufferedReader(new FileReader(filePath))) {
            String line;
            while ((line = br.readLine()) != null) {
                content.append(line).append("\n");
            }
        } catch (IOException e) {
            return "读取文件失败，错误原因：" + e.getMessage();
        }
        return "文件内容：\n" + content.toString();
    }
}

# ## 二、MCP 是什么？（通俗解释+核心作用）

# ### 1. 通俗解释（一句话懂）

MCP（Method Call Protocol，方法调用协议），简单说就是「本地程序暴露的“接口”」，比如你本地写了一个Java接口（SpringBoot接口），MCP就是这个接口的调用规则，Agent可以通过MCP，调用这个本地接口，完成复杂的本地任务。

和本地Skill的区别：Skill是“本地类方法”，Agent直接调用；MCP是“本地接口”，Agent通过HTTP请求调用（类似调用云端API），更适合复杂的本地服务（比如本地SpringBoot项目）。

举个例子：你本地有一个SpringBoot接口，功能是“查询本地MySQL数据库中的用户信息”，Agent可以通过MCP调用这个接口，获取用户数据，不用直接操作数据库。

# ### 2. 核心作用

  1. 适配本地服务：调用本地SpringBoot、SpringCloud等项目的接口，实现复杂业务逻辑；

  2. 解耦Agent和本地程序：Agent不用依赖本地程序的代码，只需要调用接口，修改本地程序不影响Agent；

  3. 支持多语言协作：本地程序可以是Java、Python等任意语言，只要暴露MCP接口，Agent就能调用。

# 2.1 编写MCP调用工具类（HTTP请求，调用本地接口）
import dev.langchain4j.agent.tool.Tool;
import org.apache.hc.client5.http.fluent.Request;
import org.apache.hc.core5.http.HttpResponse;

import java.io.IOException;

/**
 * MCP调用工具类：Agent通过这个类，调用本地MCP接口
 */
public class LocalMcpCallTool {

    // 本地MCP接口的基础地址（SpringBoot项目的地址）
    private static final String MCP_BASE_URL = "http://localhost:8080/mcp";

    /**
     * 调用本地MCP接口：根据id查询用户
     * @param userId 用户id
     * @return 用户信息（JSON格式）
     */
    @Tool(description = "调用本地MCP接口查询用户信息，参数是用户id，返回JSON格式的用户信息，接口地址是" + MCP_BASE_URL + "/user/{id}")
    public String callUserMcp(Long userId) {
        try {
            // 发送HTTP GET请求，调用本地MCP接口
            HttpResponse response = Request.get(MCP_BASE_URL + "/user/" + userId)
                    .execute()
                    .returnResponse();

            // 读取接口返回的内容（JSON）
            String responseBody = new String(response.getEntity().getContent().readAllBytes());
            return "MCP接口调用成功，返回用户信息：\n" + responseBody;
        } catch (IOException e) {
            return "MCP接口调用失败，错误原因：" + e.getMessage();
        }
    }
}

# ## 三、怎么编写Tools，提供给Agent调用？（通用模板+注意事项）

不管是本地Skill，还是MCP调用工具，本质都是「Agent可以调用的Tool」，编写有固定模板，记住以下3点，就能编写任意Tool。

# ### 1. Tool编写通用模板（Java版）

import dev.langchain4j.agent.tool.Tool;

/**
 * Agent Tool 通用模板
 * 说明：一个Tool类可以包含多个Tool方法，每个方法对应一个具体功能
 */
public class CustomAgentTool {

    // 工具方法1：具体功能（比如本地文件写入）
    @Tool(description = "描述这个工具能做什么，需要什么参数，返回什么结果，越详细越好")
    public String toolMethod1(String param1, Integer param2) {
        // 1. 编写具体的功能逻辑（Java代码）
        // 2. 处理参数，执行任务
        // 3. 返回结果（Agent会接收这个结果，继续执行后续步骤）
        return "工具执行成功，结果：xxx";
    }

    // 工具方法2：另一个功能（比如本地数据计算）
    @Tool(description = "描述这个工具能做什么，需要什么参数，返回什么结果")
    public Integer toolMethod2(Integer num1, Integer num2) {
        return num1 + num2; // 示例：两数相加
    }
}

# ### 2. 核心注意事项（必记）

  2. description要详细：要写清楚“工具能做什么、需要什么参数、返回什么结果”，比如“读取本地文件，参数是文件完整路径，返回文件内容”，Agent才能正确判断什么时候用、怎么传参；

  3. 方法参数要明确：参数类型（String、Integer等）要清晰，不要用复杂的自定义对象（Agent难以处理），如果需要多个参数，尽量拆分；

  4. 返回结果要简洁：返回Agent能理解的内容（比如文本、JSON），不要返回复杂的对象；

  5. 异常处理：一定要捕获异常，返回错误信息（比如文件读取失败、接口调用失败），避免Agent执行中断。

# ### 3. 进阶：多个Tool组合使用（Java案例）

import dev.langchain4j.agent.AgentExecutor;

        DoubaoChatModel model = Config.getDoubaoModel();

        // 2. 实例化多个Tool

        String result = AgentExecutor.execute(agent, goal);

        // 6. 打印结果
        System.out.println("Agent调用多个Tool结果：\n" + result);
    }
}

# # 七、常见问题（避坑）：Java实践中最容易踩的坑

  1. 坑1：API密钥错误 → 解决：检查豆包API密钥是否复制正确，没有多余空格，若密钥过期，重新申请；

  2. 坑2：Java版本不兼容 → 解决：严格使用Java 11或Java 17（稳定版），避免使用Java 8及以下版本（不支持LangChain4j部分依赖），也不要用过高版本（可能出现依赖冲突）；

  3. 坑3：Maven依赖下载失败 → 解决：检查pom.xml中依赖的版本是否正确（文中版本均为稳定兼容版），刷新Maven时勾选“Force Update of Snapshots/Releases”，若仍失败，可手动删除本地Maven仓库对应依赖，重新下载；

  4. 坑4：Agent无法调用本地Skill/MCP工具 → 解决：① 检查工具类是否添加@Tool注解，description描述是否清晰；② 确认工具类已正确注入Agent（builder().tools(工具实例)）；③ 检查本地Skill路径、MCP接口地址是否正确，避免路径写错、端口冲突；

  5. 坑5：运行Agent时报“无权限访问本地文件” → 解决：检查本地文件路径是否正确（如D:/test.txt，不要漏写盘符、写错分隔符），同时确保Java程序有本地文件读写权限（Windows系统可右键文件→属性→安全，赋予读写权限）；

  6. 坑6：MCP接口调用失败 → 解决：① 确认本地SpringBoot项目已启动，接口地址、端口与工具类中MCP_BASE_URL一致；② 用Postman先测试MCP接口是否能正常返回数据，排除接口本身错误；③ 检查防火墙是否拦截本地HTTP请求；

  7. 坑7：代码中出现转义字符错误（如XML标签报错） → 解决：复制文中代码时，确保XML标签（如pom.xml中）的尖括号、转义字符（<、>）正确，不要手动修改代码中的转义格式，直接复制粘贴即可；

  8. 坑8：Agent执行结果不符合预期（如未生成指定代码） → 解决：下达目标时尽量详细，明确要求（如“生成Java实体类，包含哪些字段、添加哪些方法”），避免模糊表述；同时检查大模型API密钥是否有效，网络是否正常；

  9. 坑9：本地Skill中出现IO异常、空指针异常 → 解决：严格按照文中Tool编写规范，添加异常捕获代码，避免未处理的异常导致Agent执行中断；同时检查方法参数是否为空（如文件路径为空、用户id为空）；

  10. 坑10：LangChain4j依赖冲突 → 解决：不要随意修改文中给出的依赖版本，若项目中已有其他版本的LangChain4j相关依赖，统一调整为文中的0.24.0版本，避免版本不兼容。
