interface MyInterface {
    int sum(int i, int j);

这是 Java 8 引入的 java.util.function 包中的内置函数式接口整理。先记 4 个核心，其余大多是它们的双参数版或基本类型特化版。

# 一、四大核心接口（必记）

接口 抽象方法 含义 典型场景
Supplier<T> T get() 供给者：无参，返回一个结果 工厂、延迟加载、随机数
Consumer<T> void accept(T t) 消费者：接收一个参数，无返回值 forEach、打印、写日志
Function<T, R> R apply(T t) 函数：接收一个参数，返回一个结果 数据转换、映射
Predicate<T> boolean test(T t) 断言：接收一个参数，返回 true/false 过滤、条件判断

示例：

Supplier<String> s = () -> "hello";
Consumer<String> c = str -> System.out.println(str);
Function<String, Integer> f = str -> str.length();
Predicate<String> p = str -> str.isEmpty();

# 二、双参数版本（Bi 开头）

接口 抽象方法 含义 典型场景
BiConsumer<T, U> void accept(T t, U u) 接收两个参数，无返回值 Map.forEach((k,v) -> ...)
BiFunction<T, U, R> R apply(T t, U u) 接收两个参数，返回一个结果 reduce、合并计算
BiPredicate<T, U> boolean test(T t, U u) 接收两个参数，返回布尔值 双条件判断

示例：

BiConsumer<String, Integer> bc = (name, age) -> System.out.println(name + age);
BiFunction<Integer, Integer, Integer> bf = (a, b) -> a + b;
BiPredicate<String, String> bp = (s1, s2) -> s1.equals(s2);

# 三、Operator 系列（输入输出类型相同）

LongBinaryOperator long applyAsLong(long, long) long 二元运算
DoubleBinaryOperator double applyAsDouble(double, double) double 二元运算

示例：

BinaryOperator<Integer> bo = (a, b) -> a + b;

# 十、Stream 中的常见对应关系

Stream 方法 使用的函数式接口
filter() Predicate<T>
map() Function<T, R>
forEach() Consumer<T>
reduce() BinaryOperator<T>
mapToInt() ToIntFunction<T>

实际开发建议： 日常 90% 以上只用 Supplier、Consumer、Function、Predicate 以及 BiConsumer、BiFunction；其余多为 Stream 内部或性能优化场景使用，用到时再查即可。

# 3、StreamAPI

最佳实战：以后凡是你写for循环处理数据的统一全部用StreamAPI进行替换； Stream所有数据和操作被组合成流管道流管道组成：

  • 一个数据源（可以是一个数组、集合、生成器函数、I/O管道）
  • 零或多个中间操作（将一个流变形成另一个流）
  • 一个终止操作（产生最终结果）

Java 8 的 Stream 方法可以分成：创建流 → 中间操作 → 终止操作。中间操作返回新 Stream（惰性）；终止操作触发实际计算并产出结果。

# 一、创建 Stream（入口）

方法 作用 使用场景
Collection.stream() 集合转顺序流 list.stream() 最常用
Collection.parallelStream() 集合转并行流 数据量大、计算可并行
Arrays.stream(T[]) 数组转流 数组处理
Stream.of(T...) 元素直接成流 少量固定元素
Stream.iterate(seed, f) 无限递增序列 生成数列、斐波那契
Stream.generate(Supplier) 无限随机/供给序列 生成 UUID、随机数
Files.lines(Path) 按行读文件 大文件逐行处理
Pattern.splitAsStream() 正则拆分字符串 复杂分隔
IntStream.range(0, n) int 范围流 循环替代 for

# 二、中间操作（Intermediate）

特点：返回 Stream，可链式调用，惰性执行（不调终止操作不会真正计算）

# 1. 过滤 / 切片

方法 作用 使用场景
filter(Predicate) 按条件保留元素 筛选年龄>18、状态=启用
distinct() 去重（依赖 equals） 去重用户 ID、订单号
limit(long n) 只取前 n 个 分页、取 Top N
skip(long n) 跳过前 n 个 分页第二页、跳过表头
takeWhile(Predicate) Java 9+：从头取，遇 false 停止 有序数据前缀截取
dropWhile(Predicate) Java 9+：从头丢，遇 false 后全留 跳过有序前缀

# 2. 映射 / 转换

方法 作用 使用场景
map(Function) 一对一转换 User → name、String → length

mapToLong(ToLongFunction) 转 LongStream 大整数统计
mapToDouble(ToDoubleFunction) 转 DoubleStream 价格、评分计算
flatMap(Function→Stream) 一对多压平 List<List<T>> 展平、拆句子
flatMapToInt/Long/Double 压平为基本类型流 嵌套数组数值计算

# 3. 排序

方法 作用 使用场景

sorted(Comparator) 自定义排序 按年龄、价格、多字段排序

# 4. 窥视 / 调试

方法 作用 使用场景
peek(Consumer) 处理每个元素但不改变流 调试打印中间结果

# 5. 并行相关

# 4、Reactive-Stream

2013 年前后，由 Netflix、Lightbend、Pivotal（Spring）等厂商共同制定了 JVM 上的一套异步流式数据交换规范：

  • Publisher：发数据
  • Subscriber：收数据
  • Subscription：订阅关系 + 背压（request(n)）
  • Processor：既是 Publisher 又是 Subscriber

目标：不同库之间可以互操作，且在高负载下不会把下游压垮。

官网：reactive-streams.org (opens new window)

  • 规范仓库：reactive-streams/reactive-streams-jvm（GitHub）
  • Maven 坐标：
    <dependency>
  <groupId>org.reactivestreams</groupId>
  <artifactId>reactive-streams</artifactId>
  <version>1.0.4</version>
</dependency>

java jdk1.9 通过 java.util.concurrent.Flow 包 实现了 这一标准

注意：org.reactivestreams.* 与 java.util.concurrent.Flow.* 在 Java 里是两种不同类型，不能直接赋值，需通过 org.reactivestreams.FlowAdapters 转换。

# 规范要求的四个特性

  1. 可处理 0～N 个元素（N 可以是无穷，例如消息流、事件流）
  2. 同一流内元素有序传递
  3. Publisher 与 Subscriber 之间异步传递（通过 Subscription 建立订阅关系）
  4. 必须非阻塞，并支持背压（Backpressure）：下游通过 Subscription.request(n) 按需拉取，上游按请求推送，避免下游被压垮

推荐阅读： 响应式宣言：https://www.reactivemanifesto.org/zh-CN ReactiveStream: https://github.com/reactive-streams/reactive-streams-jvm/blob/v1.0.4/README.md

响应式系统:基于异步、消息驱动的全事件回调系统

API Components：
    1、Publisher：发布者；产生数据流
    2、Subscriber：订阅者； 消费数据流
    3、Subscription：订阅关系；
        1、订阅关系是发布者和订阅者之间的关键接口。订阅者通过订阅来表示对发布者产生的数据的兴趣。订阅者可以请求一定数量的元素，也可以取消订阅。
    4、Processor：处理器；
        1、处理器是同时实现了发布者和订阅者接口的组件。它可以接收来自一个发布者的数据，进行处理，并将结果发布给下一个订阅者。处理器在Reactor中充当中间环节，代表一个处理阶段，允许你在数据流中进行转换、过滤和其他操作。

响应式编程：

1、底层：基于数据缓冲队列 + 消息驱动模型 + 异步回调机制

2、编码：流式编程 + 链式调用 + 声明式API

少量线程一直执行(CPU 数量的线程) > 大量线程频繁切换

# 二、需要先了解的概念

# 1. Reactive Streams 规范

2013 年前后 Netflix、Lightbend、Pivotal 等共同制定的 JVM 异步流互操作规范。

角色 职责
Publisher 发布数据
Subscriber 消费数据
Subscription 订阅关系；request(n) 控制背压
Processor 既是 Publisher 又是 Subscriber

规范要点：

  1. 0～N 个元素，同一流内有序
  2. Publisher → Subscriber 异步传递
  3. 背压：下游 request(n)，上游按量推送

Maven：org.reactivestreams:reactive-streams:1.0.4

JDK 9 的 java.util.concurrent.Flow 与 org.reactivestreams.* 类型不通用，互转用 FlowAdapters。

# 2. 惰性执行：subscribe 才跑

和 Stream 的终止操作类似：链上写操作符不会执行，调用 subscribe() 才触发。

Flux<Integer> flux = Flux.range(1, 3);  // 此时什么都没发生
flux.subscribe(System.out::println);     // 1 2 3

# 3. 冷流 vs 热流

冷流 热流
行为 每个订阅者从头收一遍 只收订阅之后的数据
典型 API Flux.just、Mono.fromCallable Flux.interval、Sinks
场景 HTTP 请求、DB 查询 定时 tick、消息广播

# 4. 背压（Backpressure）

下游处理不过来时，通过 Subscription.request(n) 告诉上游「一次最多给 n 个」。

  • Lambda 版 subscribe(Consumer) 默认 request(Long.MAX_VALUE)，等于不限速
  • 要手动控速：用 BaseSubscriber 或带 Consumer<Subscription> 的 subscribe

Supplier<T> get defer、fromCallable
Stream Reactor

中间操作 返回 Stream 返回 Publisher
异步 基本同步 天生异步
