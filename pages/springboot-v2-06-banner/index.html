SpringBoot入门 - 定制自己的Banner

# SpringBoot入门 - 定制自己的Banner

本文基于 06.SpringBoot入门 - 定制自己的Banner.md 优化，供比对。

# 导读

启动 Spring Boot 应用时，控制台会先打印一段 ASCII 艺术字和版本信息——这就是 Banner。它不影响业务逻辑，却是团队品牌、环境标识的第一张「名片」。本篇从「能改」到「改得好」，再到源码级理解 Banner 加载顺序，帮你把启动日志变成可控、可维护的配置项。

读完本篇你能做到：

  • 用 banner.txt 或代码方式自定义启动 Banner
  • 在 Banner 中嵌入版本号、应用名等占位变量
  • 理解文字 / 图片 Banner 的优先级与底层实现
  • 避开生产环境滥用 Banner 的常见坑

# 核心概念

概念 说明
Banner 应用启动时在控制台（或日志）输出的装饰性文本，默认由 SpringBootBanner 提供
banner.txt 放在 classpath 根目录（通常 src/main/resources/）的纯文本 Banner 文件
Banner.Mode 控制输出目标：CONSOLE（默认）、LOG、OFF
ImageBanner Spring Boot 2.x 支持将 gif/jpg/png 转为 ASCII 字符画输出
占位变量 Banner 文本中的 ${...}，启动时由 Environment 解析替换

Banner 的定制属于体验层配置，与自动装配、Bean 生命周期无耦合，改完重启即可生效（DevTools 热重启同样适用）。

# 什么时候值得定制？

场景 建议
公司内部多微服务 统一 Banner 模板 + ${application.title} 区分服务名
开源 / 演示项目 展示品牌 ASCII，提升辨识度
生产 fat Jar 通常 关闭 Banner（spring.main.banner-mode=off），减少日志噪音
单元测试 new SpringApplicationBuilder().bannerMode(OFF) 加速启动

团队可约定：banner.txt 纳入 Git 管理，禁止在 Banner 中写密钥或内网地址；敏感环境信息应走配置中心而非启动图。

# 方式对比：三种定制入口

方式 配置位置 适用场景 优先级
默认 banner.txt resources/banner.txt，无需额外配置 绝大多数项目 中（次于图片）
显式指定 location spring.banner.location 多模块、Banner 放独立资源包 中
SpringApplication API setBannerMode / setBanner 编程关闭、单元测试、动态 Banner 最高（代码层）
图片 Banner spring.banner.image.location 或 banner.{gif,jpg,png} 演示、个人项目 高（优先于 txt）

加载优先级（Spring Boot 2.x）： 图片 Banner → banner.txt（或 spring.banner.location）→ 内置 SpringBootBanner。

        SpringApplication app = new SpringApplication(DemoApplication.class);

# 占位变量与 ANSI 着色

banner.txt 支持 Spring 内置占位符，便于在启动时展示版本与构建信息：

${spring-boot.version}              # 如 2.5.14
${spring-boot.formatted-version}    # 如 (v2.5.14)
${application.version}              # MANIFEST.MF 中的 Implementation-Version
${application.formatted-version}    # 带括号的格式化版本
${application.title}                # MANIFEST.MF 中的 Implementation-Title
${AnsiColor.GREEN}                  # ANSI 前景色
${AnsiBackground.BLUE}              # ANSI 背景色
${AnsiStyle.BOLD}                   # 粗体等样式

# 图片 Banner（了解）

Spring Boot 2 支持将图片转为控制台 ASCII 字符画：

spring:
  main:
    banner-mode: console
  banner:
    charset: UTF-8
    image:
      margin: 0
      height: 10        # 输出高度（字符行数）
      invert: false     # 是否反色
      location: classpath:logo.png

也支持在 classpath 根目录放置 banner.gif / banner.jpg / banner.png，无需额外配置即可被自动发现。

现实建议： 图片转 ASCII 对分辨率、对比度敏感，终端字体不一致时效果参差，团队项目极少采用；文字 Banner + 占位变量已足够。

图片过大可能触发：

Image banner not printable: ... (ArrayIndexOutOfBoundsException: '4096')
1

应控制图片尺寸，或降低 height 参数。

GIF 动图会按帧循环输出，在 CI 控制台中可能刷屏；流水线环境建议统一 spring.main.banner-mode=off，本地开发再打开，保持日志可读性。

# 源码视角：Banner 如何被加载

核心类：SpringApplicationBannerPrinter。

1. 获取 Banner 链

private Banner getBanner(Environment environment) {
    Banners banners = new Banners();
    banners.addIfNotNull(getImageBanner(environment));  // 图片优先
    banners.addIfNotNull(getTextBanner(environment));   // 其次 banner.txt
    return banners.hasAtLeastOneBanner() ? banners : DEFAULT_BANNER;
}

2. 图片发现规则

  • 配置了 spring.banner.image.location → 加载指定资源
  • 否则依次尝试 banner.gif、banner.jpg、banner.png

3. ASCII 转换

ImageBanner 逐像素读取颜色，映射到最接近的 ANSI 颜色，再按亮度选择字符（如 @、#、.），最终输出到 PrintStream。

理解这条链路后，遇到「改了 txt 没生效」，应优先排查：是否 classpath 下存在同名图片 Banner 覆盖了文本。

# 与 Spring Boot 3 的差异提示

Spring Boot 3 将自动配置注册文件从 META-INF/spring.factories 迁移到 META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports，但 Banner 机制保持不变。若你从 2.5 升级到 3.x，现有 banner.txt 通常可直接复用，仅需验证 ANSI 在所用终端下的显示效果。

# 常见坑

现象 原因 处理
修改 banner.txt 不生效 classpath 存在 banner.png 等图片 删除图片或改 spring.banner.image.location
${application.version} 为空 未打包，MANIFEST 未生成 mvn package 后 java -jar 运行
中文乱码 编码不一致 设置 spring.banner.charset=UTF-8，文件保存为 UTF-8
生产日志臃肿 Banner 写入 LOG 模式 生产用 Banner.Mode.OFF 或 spring.main.banner-mode=off
CI 日志解析失败 ANSI 转义序列干扰 关闭着色或设置 spring.output.ansi.enabled=never

# 多模块项目放置位置

结构 banner.txt 位置 说明
单模块 src/main/resources/banner.txt 最常见
多模块父工程 仅 启动模块 的 resources 只有 main 模块 classpath 生效
独立 banner 包 spring.banner.location=classpath:meta/banner.txt 便于复用

若子模块也被打包进 fat Jar，注意避免多个 banner.txt 冲突；最终生效取决于 SpringApplication 使用的 ResourceLoader 与 classpath 顺序。

配合 Spring Boot Admin 或 K8s 部署时，启动日志往往被采集系统完整保存；精简 Banner 或关闭 ANSI 着色，有利于日志检索与告警规则匹配。

# 本篇小结

  • Banner 是启动时的展示层配置，默认加载顺序为：图片 > banner.txt > 内置 Banner。
  • 日常推荐 banner.txt + 占位变量，简单、可版本管理、跨环境一致。
  • 代码层可用 Banner.Mode 在测试 / 生产差异化关闭输出。
  • ${application.*} 变量依赖 Jar 的 MANIFEST，本地 IDE 直跑时要注意差异。
