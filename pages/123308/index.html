# LangChain4J的核心架构

这张图展示了 LangChain（或类似大语言模型应用开发框架） 的核心模块架构，它清晰地划分了构建 LLM 应用的关键组件层级，我们一层一层来拆解：

# 1. 最上层：应用编排层

这一层是面向最终业务场景的“胶水层”，负责把基础能力串联成完整的应用流程：

  • Chains（链）：将多个组件（模型、提示词、工具、RAG 流程等）按顺序组合成可执行的工作流，实现复杂逻辑的串联，比如“先检索知识 → 再生成回答 → 再格式化输出”。
  • AI Services（高阶Api调用）：基于底层能力封装的、直接可调用的业务级服务，比如对话机器人、问答系统、文档助手等，是最终交付给用户的产品形态。

# 2. 左下：Basics（基础核心层）

这是构建所有 LLM 应用的基础组件，相当于框架的“地基”：

  • Language Models（语言模型）：核心的大语言模型接口，比如 OpenAI GPT、Claude、本地开源模型（Ollama、Qwen）等，是生成文本的核心引擎。
  • Prompt Templates（提示词模板）：可复用的提示词模板，用于标准化输入格式，比如定义系统角色、输入变量占位符，避免每次手动写重复提示词。
  • Output Parsers（输出解析器）：把模型返回的非结构化文本，转换成程序可处理的结构化数据（如 JSON、列表、对象），解决模型输出格式不统一的问题。
  • Memory（记忆模块）：为对话/应用提供上下文记忆能力，比如存储历史对话、用户偏好，让模型能理解多轮对话的上下文。

# 3. 右下：RAG（检索增强生成层）

这是解决“模型知识过时/不具备私有知识”的关键模块，也是目前企业级 LLM 应用的核心技术：

  • Document Loaders（文档加载器）：从不同来源（PDF、Word、网页、数据库等）读取和加载数据，统一转换成框架可处理的文档格式。
  • Document Splitters（文档分割器）：把长文档切分成适合模型处理的小块（chunk），解决模型上下文窗口限制，同时提升检索效率。
  • Embedding Models（嵌入模型）：把文本转换成向量（Embedding），实现语义级的匹配和检索，比如把用户问题和知识库文本都转成向量，再找最相似的内容。
  • Embedding Stores（向量存储）：专门存储向量数据的数据库（如 Pinecone、Chroma、FAISS），支持高效的相似性检索，是 RAG 实现的核心存储组件。

# 💡 整体架构的逻辑关系

这张图其实体现了一个从“基础组件 → 能力模块 → 应用服务”的分层设计：

  1. Basics 提供了和大模型交互的最基础能力（调用模型、写提示词、解析输出、记忆上下文）；
  2. RAG 是在基础能力之上，扩展了“私有知识检索”的能力，让模型能用上外部数据；
  3. Chains 把这些基础和 RAG 能力串联起来，形成完整的工作流；
  4. 最终封装成 AI Services，交付给用户使用。

这种分层设计的好处是解耦和复用：你可以替换不同的语言模型、向量数据库，也可以调整 RAG 流程，而不用改动上层的业务逻辑。

# 2.3 思考 : 怎么存在多种大模型产品在系统里共存使用？

  • 多种大模型共存：同一应用中通过 多个 @Bean + @Qualifier/@Resource(name=...) 管理多 ChatModel 实例。
注解 来源 默认注入规则 多 Bean 冲突时 是否需要额外注解 推荐场景
@Autowired Spring 自带 按类型 ByType 直接报错 必须配合 @Qualifier 指定 Bean 名 统一按类型注入 直接报错 必须配合 @Qualifier 指定 Bean 名 统一按类型注入
@Resource JSR-250 Java 标准 先按名称 ByName ,名称找不到再按类型 按变量名匹配，匹配不到再按类型 不需要额外注解，可直接用name指定 多实例 Bean 首选，代码更简洁

因为可能存在多个 ChatModel 类型的对象，比如像千问、deepseek、doubao 等 多种大语言模型介入，此时就会出现Spring容器中同一种类型的对象，存在多个名称的情况。 此时再单独使用 @AutoWired 注解就会报错，需要配合使用@Qualifier 注解来指定使用哪一种大模型对象，如下:


@Autowired
@Qualifier("qwenChatModel") // 明确指定：我要通义千问
private ChatModel chatModel;

# 四、LangChain4j 之底阶和高阶 API

LangChain4j 是Java 生态的 LLM 开发框架，严格区分 Low level（低阶/底层 API） 和 High level（高阶/顶层 API），二者是 层级依赖关系： 高阶 API 基于低阶 API 封装，低阶 API 提供原子能力，高阶 API 提供开箱即用的业务能力。

下面从核心定义、实现原理、包含组件、属性/方法、核心区别做完整详细梳理。

# 一、核心定义

# 1. Low level API（低阶 API）

  • 定位：原子化、细粒度、基础构建块，对应 LangChain 架构的 Basics + RAG 基础组件
  • 作用：提供与大模型、向量库、文档、提示词交互的最小功能单元
  • 特点：灵活度极高、需要手动组装逻辑、代码量较大、适合定制化开发
  • 对应包：dev.langchain4j.model、dev.langchain4j.rag、dev.langchain4j.memory 等基础包

# 2. High level API（高阶 API）

  • 定位：自动化、封装化、业务化，对应 LangChain 架构的 Chains + AI Services
  • 作用：将低阶组件自动组装，屏蔽底层细节，一行代码实现完整功能
  • 特点：极简使用、开箱即用、灵活度较低、适合快速开发标准业务
  • 核心载体：AiServices（Java 动态代理封装）、Chain 工作流

# 二、核心组件、属性、实现方式 详细对比

# 1. Low level API 全清单

低阶 API 是独立的 Java 类/接口，每个组件只做一件事，手动配置、手动调用。

模块分类 核心接口/类 核心属性 核心功能 实现方式

/**

public class TokenListener implements ChatModelListener {


    private static final ThreadLocal<TokenUsageInfo> threadLocal = new ThreadLocal<>();

    @Override
    public void onRequest(ChatModelRequestContext requestContext) {
        System.out.println("本次对话内容：" + requestContext.toString());
        ChatModelListener.super.onRequest(requestContext);
        threadLocal.set(new TokenUsageInfo());
    }

    @Override
    public void onResponse(ChatModelResponseContext responseContext) {
        System.out.println("本次对话 输入消耗的token：" + responseContext.chatResponse().tokenUsage().inputTokenCount());
        System.out.println("本次对话 输出消耗的token：" + responseContext.chatResponse().tokenUsage().outputTokenCount());
        System.out.println("本次对话 总消耗token：" + responseContext.chatResponse().tokenUsage().totalTokenCount());

        threadLocal.get().setInputTokens(responseContext.chatResponse().tokenUsage().inputTokenCount());
        threadLocal.get().setOutputTokens(responseContext.chatResponse().tokenUsage().outputTokenCount());
        threadLocal.get().setTotalTokens(responseContext.chatResponse().tokenUsage().totalTokenCount());
    }

    @Override
    public void onError(ChatModelErrorContext errorContext) {
        System.out.println("出错了。。。");
        ChatModelListener.super.onError(errorContext);
    }

    public static TokenUsageInfo getCurrentTokenUsage() {
        return threadLocal.get();
    }

    public static void clear() {
        threadLocal.remove();
    }

    @lombok.Data
    public static class TokenUsageInfo {
        private long requestId;
        private int inputTokens;
        private int outputTokens;
        private int totalTokens;
    }
}

    @Value("classpath:static/images/mi.jpg")
    private Resource resource;//import org.springframework.core.io.Resource;

    /**
     * @Description: 通过Base64编码将图片转化为字符串
     *              结合ImageContent和TextContent形成UserMessage一起发送到模型进行处理。
     * @Auther: zzyybs@126.com
     *
     *测试地址：http://localhost:9006/image/call
     */
    @GetMapping(value = "/image/call")
    public String readImageContent() throws IOException {
        String result = null;

        //第一步，图片转码：通过Base64编码将图片转化为字符串
        byte[] byteArray = resource.getContentAsByteArray();
        String base64Data = Base64.getEncoder().encodeToString(byteArray);

        //第二步，提示词指定：结合ImageContent和TextContent一起发送到模型进行处理。
        UserMessage userMessage = UserMessage.from(
                TextContent.from("从下面图片种获取来源网站名称，股价走势和5月30号股价"),
                ImageContent.from(base64Data, "image/jpg")
        );
        //第三步，API调用：使用OpenAiChatModel来构建请求，并通过chat()方法调用模型。
        //请求内容包括文本提示和图片，模型会根据输入返回分析结果。
        ChatResponse chatResponse = chatModel.chat(userMessage);

        //第四步，解析与输出：从ChatResponse中获取AI大模型的回复，打印出处理后的结果。
        result = chatResponse.aiMessage().text();

        //后台打印
        System.out.println(result);

        //返回前台
        return result;
    }
}

# 12.1 向量与向量化

# 12.1.1 什么是向量？

向量就是 一组有序、固定顺序的数字，用来同时描述一个事物的多个特征 / 方向； 格式：写成 [数字1, 数字2, 数字3, ……] 其中数字的个数叫维度，每个数字对应 1 个特征。

二维向量（平面）：[2, 3] 含义：平面上，向右走 2 单位、向上走 3 单位；也可以表示一个点 (2,3)。

三维向量（空间）：[5, 2, 4] 含义：长 5、宽 2、高 4；或空间里的一个方向 / 位置。

AI 里的向量（高维向量，核心）:AI 不用 2/3 维，用几十～几千维的高维向量，没有几何直观，只用来代表语义 / 特征。

# 举例（直白易懂）

1、描述一个人的 4 维向量 特征：身高、体重、年龄、学历（本科 = 3） 向量：[175, 66, 24, 3] 4 个数字 = 4 维向量，每个数字对应一个特征。

2、描述一杯奶茶的 5 维向量 特征：甜度、冰量、价格、咖啡因、奶含量 向量：[3, 2, 18, 0.4, 0.8]

3、大模型里的句子向量（768 维） 句子：今天天气很好 向量：[0.12, -0.34, 0.77, -0.09, ……]（一共 768 个小数） 每个小数代表某一类语义倾向，比如天气、心情、时间等。

向量化：把文字、图片、类别、声音等非数字信息，通过嵌入模型（Embedding Model） 转换成固定长度向量的过程。

# 十三、LangChain4j 之检索增强生成（RAG）

RAG =Retrieval-Augmented Generation(检索增强生成)

  • Langchain4j官网RAG 教程 (opens new window)

LLM 的知识仅限于其训练数据。若想让 LLM 掌握领域特定知识或专有数据，你可以：

  • 使用我们将在本节介绍的检索增强生成（RAG）技术
  • 使用你的数据对大语言模型进行微调
  • 将RAG与微调结合 (opens new window)

# 13.1 是什么

RAG 就是在将提示词发送给大语言模型（LLM）之前，从你的数据中检索并注入相关信息片段的方法。通过这种方式，大语言模型（LLM）将获取到（有望是）相关的信息，并能够利用这些信息进行回复，这应当能降低产生幻觉的概率。

RAG（Retrieval-Augmented Generation）**：检索增强生成，缓解 幻觉

  • 核心理念：先检索外部知识，再生成答案——课件比喻为「开卷小抄」。

什么是大模型幻觉？ 1、已读乱回 2、已读不回 3、似是而非

# 13.3 RAG能干嘛？

通过引入外部知识源来增强LLM的输出能力，传统的LLM通常基于其训练数据生成响应，但这些数据可能过时或不够全面，RAG允许模型在生成答案之前，从特定的知识库中检索相关信息，从而提供更准确和上下文相关的回答

# 13.4 RAG 怎么玩？

RAG 流程分为两个不同的阶段：索引阶段(Indexing)和检索阶段(Retrieval)。LangChain4j 为这两个阶段都提供了工具支持。

# 十四、MCP（模型上下文协议 Model Context Protocol）

# 什么是MCP？

Model Context Protocol(模型上下文协议) 简称MCP，官网地址 (opens new window)

官网给出来的解释是:MCP（模型上下文协议）是一种用于将人工智能应用程序连接到外部系统的开源标准。

借助于MCP。Claude、ChatGPT 等人工智能应用程序可以连接到数据源（例如本地文件、数据库）、工具（例如搜索引擎、计算器）和工作流（例如专用提示词），从而获取关键信息并执行任务。

可以将 MCP 想象成 AI 应用的 USB‑C 接口。就像 USB‑C 为电子设备的连接提供了标准化方式一样，MCP 为 AI 应用与外部系统的连接提供了标准化方案。

# langchain4j 支持MCP协议官网：

MCP 教程 (opens new window)

# MCP能干嘛？

  • 相对 Function Calling 更高一层抽象，是 Agent 的重要基础之一。

# MCP的架构

MCP（Model Context Protocol，模型上下文协议）的核心架构是客户端 - 主机 - 服务器（Client-Host-Server）三元架构，基于JSON-RPC 2.0构建有状态会话协议，实现大模型与外部工具 / 数据源的标准化交互，被誉为 AI 世界的 “USB-C 接口”。

组件 核心定位 核心定位 典型实例
MCP Host（主机） 大脑 / 协调者 1. 承载 LLM 并处理用户交互
2. 管理客户端生命周期
3. 路由工具调用至对应客户端
4. 聚合多服务器的上下文与能力
5. 执行安全策略与权限控制		 Claude Desktop、Cursor IDE、自定义 AI Agent、Spring AI 应用
MCP Client（客户端） 连接器 / 翻译官 1. 与单个 Server 建立 1:1 有状态会话
2. 协议协商与能力交换
3. 双向路由消息（LLM↔Server）
4. 模式验证与格式转换
5. 会话状态管理与订阅通知		 嵌入 Host 的通信模块（如 Spring AI 的 MCP Client Bean）
MCP Server（服务器） 工具集 / 适配器 1. 封装三类核心能力（资源 / 工具 / 提示）
2. 暴露标准化接口
3. 执行具体操作并返回结果
4. 隔离外部系统与 Host 的直接交互		 数据库查询服务、文件系统访问、API 调用代理、向量数据库检索

# MCP通信协议

MCP 使用 JSON-RPC 对消息进行编码。JSON-RPC 消息必须采用 UTF-8 编码。

该协议目前定义了两种用于客户端-服务器通信的标准传输机制： 1、stdio(标准输入输出) (opens new window)：通过标准输入和标准输出进行通信 2、Streamable HTTP (opens new window):流式请求 3、客户端和服务器也可以以可插拔的方式实现自定义传输 (opens new window)。

除了规范之外，LangChain4j 还实现了 WebSocket 传输。该传输尚未标准化，目前客户端的开发方式使其与 Quarkus MCP 服务器扩展 (opens new window)所实现的 WebSocket 传输兼容。对于那些暴露 WebSocket 但基于其他框架构建的 MCP 服务器，无法保证兼容性。

LangChain4j 还支持旧版的 HTTP/SSE transport (opens new window)，但该功能已被弃用，未来将被移除。

 * 第1步，如何进行mcp编码
 * https://docs.langchain4j.dev/tutorials/mcp#creating-an-mcp-tool-provider
 *
 * 第2步，如何使用baidu map mcp，它提供了哪些功能对外服务
 * https://mcp.so/zh/server/baidu-map/baidu-maps?tab=tools
 *
 * http://localhost:9014/mcp/chat?question=查询61.149.121.66归属地
 * http://localhost:9014/mcp/chat?question=查询北京天气
 * http://localhost:9014/mcp/chat?question=查询昌平到天安门路线规划
 */
@RestController
public class McpCallServerController
{
    @Autowired
    private StreamingChatModel streamingChatModel;

    @GetMapping("/mcp/chat")
    public Flux<String> chat(@RequestParam("question") String question)
    {
        /**1.构建McpTransport协议
         *
         * 1.1 cmd：启动 Windows 命令行解释器。
         * 1.2 /c：告诉 cmd 执行完后面的命令后关闭自身。
         * 1.3 npx：npx = npm execute package，Node.js 的一个工具，用于执行 npm 包中的可执行文件。
         * 1.4 -y 或 --yes：自动确认操作（类似于默认接受所有提示）。
         * 1.5 @baidumap/mcp-server-baidu-map：要通过 npx 执行的 npm 包名
         * 1.6 BAIDU_MAP_API_KEY 是访问百度地图开放平台API的AK
        */
        McpTransport transport = new StdioMcpTransport.Builder()
                .command(List.of("cmd", "/c", "npx", "-y", "@baidumap/mcp-server-baidu-map"))
                .environment(Map.of("BAIDU_MAP_API_KEY", System.getenv("BAIDU_MAP_API_KEY")))
                .build();

        // 2.构建McpClient客户端
        McpClient mcpClient = new DefaultMcpClient.Builder()
                .transport(transport)
                .build();

        // 3.创建工具集和原生的FunctionCalling类似
        ToolProvider toolProvider = McpToolProvider.builder()
                .mcpClients(mcpClient)
                .build();

        // 4.通过AiServivces给我们自定义接口McpService构建实现类并将工具集和大模型赋值给AiService
        McpService mcpService = AiServices.builder(McpService.class)
                .streamingChatModel(streamingChatModel)
                .toolProvider(toolProvider)
                .build();

        // 5.调用我们定义的HighApi接口,通过大模型对百度mcpserver调用
        return mcpService.chat(question);
    }
}
